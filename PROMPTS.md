# Runtime prompts

The exact runtime text is loaded from the versioned files [opening_ack.txt](src/rehearse_ai/prompts/opening_ack.txt), [decision.txt](src/rehearse_ai/prompts/decision.txt), [feedback.txt](src/rehearse_ai/prompts/feedback.txt), [early_feedback.txt](src/rehearse_ai/prompts/early_feedback.txt), and [tts_style.txt](src/rehearse_ai/prompts/tts_style.txt). This document does not duplicate their text.

The opening call receives the candidate's `greeting_response` as data and returns one short acknowledgement in structured JSON. Python checks that it is a brief statement without another question, then appends the fixed four-question briefing and readiness question. If generation or validation fails, a short generic acknowledgement is used; it does not claim knowledge of the candidate's answer. The LLM cannot choose the first project question or skip the readiness gate. The controller allows one repeat of the greeting and one repeat of the readiness prompt, and voices a “no rush” nudge once after a nonaffirmative response. Explicit stop requests remain outside LLM inference. Opening turns do not consume interview answer or follow-up budgets. The TTS style file is sent only when the configured model is `gpt-4o-mini-tts`; `tts-1` does not support speech instructions. Speed is a separate numeric provider setting.

The decision call receives the current fixed question, `current_question_answer` with all collected turns for that question joined in order, the separate turn list, the last delivered prompt, interruption context, older answers as background, and the remaining Python-owned reply allowances as JSON data. Its structured response proposes `follow_up`, `nudge`, `clarification`, `wait`, or `advance` plus text. It is instructed to keep question-two follow-ups on the technical challenge, accept a stated absence of a technical challenge, and ask for one missing detail rather than repeat a provided artifact, action, channel, or timeframe. `wait` keeps an incomplete answer open without spoken output; an exhausted allowance never authorizes automatic advancement. Python validates the action and chooses the next main question. Spoken stop/repeat/skip requests are handled outside the LLM. Normal feedback supplies 2–3 lines; early closing supplies 1–2 lines using collected answers only. No JSON response is sent directly to TTS. Candidate transcript content is treated as data, not instructions.

Offline tests check prompt loading, structured schemas, and routing. They do not establish how naturally the acknowledgement or TTS style sounds. A real listening comparison remains pending.
